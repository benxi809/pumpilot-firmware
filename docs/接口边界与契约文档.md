# Pumpilot 接口边界与契约文档 (Interface Boundary & Contract)

**项目**：Pumpilot 智慧胰岛素泵系统
**文档版本**：v1.0
**编制日期**：2026-08-04
**作用**：定义 **APP（Pumpilot 仓库）** 与 **泵体固件（pumpilot-firmware 仓库）** 之间的接口边界、数据合约与责任分工，作为两个独立项目协同开发与对接的基准。

---

## 1. 系统组成与边界

Pumpilot 系统由**两个独立交付物**组成，分别在独立仓库开发：

| 仓库 | 交付物 | 平台 | 载体 | 生命周期 |
|------|--------|------|------|----------|
| `benxi809/pumpilot` | 控制器 APP | Flutter / Android | 智能手机/平板 | 非一次性，可升级 |
| `benxi809/pumpilot-firmware` | 泵体固件 | C / nRF SDK | 一次性泵体 nRF52832 | 出厂烧录，一次性 |

**传递边界**：两者之间唯一的物理通道是 **BLE（GATT）**，遵循 **IEEE 11073-20601 / 11073-10419** 协议。

```
┌───────────────────────┐   BLE / GATT / IEEE 11073   ┌───────────────────────┐
│  Pumpilot APP         │ ◄══════════════════════════► │  泵体固件 Firmware    │
│  (controller/manager) │      (无线通信契约)            │  (agent / 泵体 nRF52832)│
└───────────────────────┘                              └───────────────────────┘
```

## 2. 责任边界（Who does what）

### 2.1 APP（控制器）职责
- 人机交互界面、治疗数据输入与展示；
- 泵二维码读取与解析、用户管理和鉴权；
- 治疗参数编辑（基础率/ICR/ISF/大剂量模板）；
- 大剂量/基础率的**剂量计算**（算法层）；
- 命令的下发编排与结果展示；
- 报警的接收、分级展示与用户交互处理；
- 历史数据存储与回顾、导出；
- 亲情号、云服务（预留）。

### 2.2 固件（泵体）职责
- 蓝牙 BLE 通信、绑定与定向广播恢复；
- **输注执行**：PWM1/PWM2 驱动微型步进电机（脉冲→胰岛素 0.00339 IU/脉冲）；
- **输注调度**：基础率 48 段、临时基础率、大剂量脉冲分配与定时执行；
- 滑动格栅（K1~K64）药量监测、霍尔信号检测（输注反馈）；
- 报警检测与上报（堵塞/泄露/耗尽/用尽等）、蜂鸣器/震动驱动；
- 时钟（连续校准，日误差≤1s）、日志存储；
- 设备出厂信息存储与上报（序列号、批号等）。

### 2.3 明确分工边界
| 事项 | 责任方 | 说明 |
|------|--------|------|
| 剂量计算（IU） | **APP** | APP 算好剂量发给泵；泵执行 |
| 脉冲换算（IU→脉冲） | **固件** | 泵根据自身机械参数换算并执行 |
| 输注时间调度 | **固件** | 泵按 3 分钟周期内部调度执行 |
| 0.00339 IU/脉冲 | **固件** | 权威参数归属泵侧（nRF52832） |
| 报警阈值检测 | **固件** | 检测硬件信号，向 APP 上报 |
| 报警分级展示 | **APP** | 按三级报警界面交互 |
| 状态机执行 | **固件** | 泵实际运行状态机 |
| 运行状态实时渲染 | **APP** | 接收并展示泵状态 |

> **关键边界原则**：APP 负责"决策/命令"，固件负责"执行/反馈"。剂量以 IU 传递，脉冲换算、物理驱动完全固件侧，避免 APP 与硬件耦合。

## 3. 通信契约（IEEE 11073）

### 3.1 物理层
- 靶标 MCU：nRF52832；
- BLE GATT：
  - Service `FFF0`
  - Characteristic `FFF1`（write / notify）
  - Characteristic `FFF2`（read）
- 绑定：首次连接使用二维码中的**蓝牙连接密码**鉴权；绑定后仅与原绑定 APP 连接，定向广播并自动恢复。
- 加密/公开两种交互状态，出厂可选。

### 3.2 协议层
遵循 **IEEE 11073-20601**（优化交换协议）+ **IEEE 11073-10419**（胰岛素泵设备专业化）。

### 3.3 对象模型契约（APP 为 manager，泵为 agent）
| 对象 | 类编码 | Handle | 归属 | 读写 |
|------|--------|:------:|:----:|:----:|
| 胰岛素泵系统 MDS | MDC_MOC_VMS_MDS_SIMP(37) | 0 | 固件 | 读 |
| 当前大剂量设置 | Metric NU(6) | 10 | 固件 | 写 |
| 大剂量延迟 | Metric NU(6) | 11 | 固件 | 写 |
| 已注射大剂量 | Metric NU(6) | 1 | 固件 | 读 |
| 当前基础率 | Metric NU(6) | 1 | 固件 | 读 |
| 已注射基础率 | Metric NU(6) | — | 固件 | 读 |
| 基础率段设置 | Metric NU(6) | — | 固件 | 读写 |
| ICR/ISF 设置 | Metric NU(6) | — | 固件 | 读写 |
| 剩余药量 | Metric NU(6) | — | 固件 | 读 |
| 胰岛素浓度 | Metric NU(6) | — | 固件 | 读 |
| 运行状态 OpStat | Metric Enum(5) | — | 固件 | 读 |
| 泵设备状态 PHD DM | Metric Enum(5) | — | 固件 | 读 |
| 泵特有状态 InsPumpStat | Metric Enum(5) | — | 固件 | 读 |
| 数据存储 PM-store | PMSTORE(61) | 6 | 固件 | 读 |
| 数据段 | PM_SEGMENT(62) | — | 固件 | 读 |
| 基础率/ICR/ISF 表存储 | SCHEDSTORE(81) | — | 固件 | 读写 |

### 3.4 OpStat 运行状态位契约
- bit0 未定 / bit1 关闭 / bit2 待机 / bit3 准备中 / bit4 初始化中 / bit5 等待 / bit6 就绪 / bit9 治疗停止 / bit10 治疗暂停 / bit11 治疗运行。
- **约束**：治疗位（stop/pause/run）至少置一位；run 仅在 op-ready 时置位。

### 3.5 InsPumpStat 泵特有状态位
air-pressure-out-of-range / bolus-canceled / delivery-max / infusion-set-detached / infusion-set-incomplete / occlusion-detected / power-insufficient / priming-issue / reservoir-empty / reservoir-issue / reservoir-low / reservoir-attached / temp-basal-canceled / temp-basal-expired / temperature-out-of-range。

## 4. 数据契约（传输字段）

### 4.1 APP → 固件（控制器下发）
| 命令/数据 | 内容 | 触发时机 |
|-----------|------|----------|
| 基础率曲线 | 48 段流速(IU/h) | 首次绑定 / 替换曲线命令 |
| 临时基础率 | 1~4 连续段，绝对/相对值 | 执行临时基础率 |
| 大剂量 | 类型(快/扩/复)、剂量、扩展时间、双波比例 | 执行大剂量 |
| 时间设置 | 年/月/日/时/分 | 首次绑定/请求 |
| 控制命令 | 开始输注/暂停/恢复/废弃/替换曲线/执行大剂量/执行临时基础率 | 用户操作 |
| 系统参数 | 启动参数、特殊注射增量 | 首次绑定 |

### 4.2 固件 → APP（泵上报）
| 数据 | 内容 | 时机 |
|------|------|------|
| 泵特征信息 | 厂编号/型号/批号/生产日期/有效期/固件版本 | 绑定/请求 |
| 一般状态 | 电量、剩余时间、初始化/准备/等待/停止/暂停/运行 | 唤醒周期/请求 |
| 工作状态 | 大剂量(执行/取消/完成)、输注超限、堵塞、药液不足、临时基础率状态 | 唤醒周期/请求 |
| 药物状态 | 已注射、剩余药量、剩余给药时间 | 唤醒周期/请求 |
| 报警信号 | 堵塞/泄露/耗尽/用尽/机械故障/自检出错等 | **立即上报** |
| 时间 | 当前泵时间 | 请求 |

### 4.3 泵特征/标识数据（出厂信息）
- 泵型号：2字母+2数字；唯一识别号：2字母+8数字；蓝牙密码：字母+数字。
- 生产批号：8位日期+2字母；有效期：8位日期；组装厂编号：2字母。
- 泵结构信息：机械模块（型号1字母+1数字+1字母，供应商1字母+2数字，批号2字母+6数字）+ PCB 信息（型号/供应商/批号/MCU型号/ID）。

## 5. 固件侧权威算法参数（APP 需知晓，勿重复上位换算）

> 以下参数为**固件侧权威值**（来源：根目录《胰岛素泵控制PCBA与固件开发需求》，nRF52832 方案）。子目录旧版（CC2541，0.005/0.05/0.1 脉冲换算）**已过时，不可用**。

- **每个脉冲**：转子转 180°，输注 **0.00339 IU**。
- PWM1/PWM2 轮流输出 20ms 宽脉冲，间隔 30ms。
- 基础率/大剂量脉冲换算与调度由**固件**完成：
  - 基础率段脉冲 = `段基础率(IU/h) × 0.5 / 0.00339`，每 3 分钟一次；不足则匀距分配。
  - 快速大剂量：`剂量 / 0.00339` 一次连续。
  - 扩展大剂量：按基础率方式分布。
  - 复合大剂量：前半 bolus、后半基础率方式。
- 格栅药量：K7(0ml) ~ K57(2ml) 共 64 格比例换算。K7 接通=用尽(一级)，K1=药量低(二级)。K65=针到位，K66=丝杆锁止。
- 报警阈值：电池<1.8V 耗尽(一级)、<2.0V 电量低(二级)；堵塞=理论输注量超格栅值 3.5IU；机械故障=连续10脉冲无霍尔；药液用尽=K7；自检出错（出厂信息不符等）。

> **APP 侧**只需下发 IU 剂量与基础率曲线，接收泵换算后的执行结果；无需在 APP 内重复做脉冲换算（架构文档中的 PulseConverter 仅用于预估/展示，真实输注以泵回执为准）。

## 6. 命令/回执与幂等契约

- **数据/命令** 传输完成需泵**校验并返回接收结果**。
- **控制命令** 泵需要**确认命令并反馈执行结果**。
- 命令带全局唯一 **操作ID**，APP 重试时复用同一 ID，泵对已执行命令幂等去重（防重复输注）——对应 APP 侧 RSK-06。
- 报警信号**一旦产生立即上报**（不等待休眠周期）。

## 7. 开发协同模式

| 方面 | APP 仓库 | 固件仓库 |
|------|----------|----------|
| 通信层 | `IPumpTransport`（BleTransport + SimulatorTransport） | BLE 服务实现（实际响应） |
| 对接验证 | SimulatorTransport 先行模拟固件行为 | 固件协议一致性测试 |
| 需求基线 | 同一 URD/SRS（APP视角） | 固件 FW-SRS（本仓库） |
| 确认测试 | 软件确认测试计划(SVTP) | 固件确认测试计划(FW-SVTP) |

**对接流程**：
1. APP 侧用 `SimulatorTransport` 模拟固件行为开发联调；
2. 固件侧实现真实 BLE 服务；
3. 以**接口契约文档**为基准做真实 APP↔固件联调；
4. 双方按契约做协议一致性验证。

---

## 8. 变更管理

- 本契约文档为 **APP 与固件的唯一对接基准**，任何协议/算法参数/对象模型的变更必须：
  1. 同步更新本**契约文档**；
  2. 在 **APP 仓库**与**固件仓库**双向评审；
  3. 更新双方追溯矩阵与确认测试。
