# Pumpilot 固件详细设计说明书

**项目名称**：Pumpilot — 睿昇胰岛素泵泵体固件（nRF52832）
**文档版本**：v1.0
**编制日期**：2026-08-04
**依据文档**：《固件架构与概要设计 v1.0》《接口边界与契约文档 v1.0》《固件软件需求说明书(FW-SRS) v1.0》《胰岛素泵控制PCBA与固件开发需求》

---

## 1. 概述

本文档对固件进行**模块级详细设计（DBD，Design Based on Detail）**，明确每个模块的组成、数据结构、函数接口、关键算法与实现要点，是 **FW-D1 ~ FW-D5** 编码的直接依据。范围涵盖：

1. 硬件抽象层（HAL/驱动）；
2. 输注控制（基础率/大剂量/临时基础率调度）；
3. 药量监测（滑动格栅蛇形映射）；
4. 报警管理；
5. BLE 通信与 IEEE 11073 agent；
6. 时钟、出厂信息、日志、电源管理。

---

## 2. 模块划分与依赖

```
┌────────────────────────────────────────────────────────────┐
│ 应用层  PumpApp · StateMachine · AlarmApp · FactoryInfo    │
├────────────────────────────────────────────────────────────┤
│ 服务层  BasalScheduler · BolusScheduler · ReservoirMonitor │
│         ClockMgr · LogManager · Ieee11073 · BleService     │
├────────────────────────────────────────────────────────────┤
│ 驱动/HAL PWM · GridScanner · Hall · ADC_Battery · Beeper   │
│         GPIO_ISR · RTC · FlashStore                        │
├────────────────────────────────────────────────────────────┤
│ 协议栈  SoftDevice (S132) / nRF5 SDK                       │
└────────────────────────────────────────────────────────────┘
```

**依赖方向**：自上而下单向依赖。应用层→服务层→驱动HAL→协议栈。禁止跨层反向调用（通过回调/事件向上传递）。

## 3. 应用层设计（App Layer）

### 3.1 PumpApp（主循环）

- 类型：`app/pump_app.c/.h`
- 组成：初始化编排 + 事件循环 + 状态机驱动。
- 关键接口：
  - `void pump_app_init(const factory_info_t *fi);` — 从 FlashStore 载入出厂信息、日志、时钟，初始化各服务。
  - `void pump_app_run(void);` — 主循环，处理队列事件。
  - `void pump_app_event_push(app_event_t ev);` — 向事件队列投递事件（ISR 上下文可调用）。

### 3.2 StateMachine（泵状态机）

- 状态定义（enum `pump_state_t`）：

| 状态 | 枚举 | 说明 |
|------|------|------|
| 仓储 | ST_WAREHOUSE | MCU 深睡，格栅簧片位于 K3；灌注唤醒 |
| 初始休眠 | ST_INIT_SLEEP | 排空初始化前的休眠态 |
| 初始化中 | ST_INITIALIZING | 贴敷进针、排空 |
| 就绪(等待) | ST_READY | 等待开始输注 |
| 运行中 | ST_RUNNING | 基础率/大剂量/临时基础率执行 |
| 治疗暂停 | ST_PAUSED | 暂停输注 |
| 废止 | ST_ABANDONED | 终止使用 |

- **状态转换表**：

| 当前状态 | 事件 | 目标状态 | 动作 |
|----------|------|----------|------|
| 仓储 | 灌注唤醒(中断) | 初始休眠 | 推杆回退触发唤醒 |
| 初始休眠 | 贴敷+启用 | 初始化中 | 进针K65→排空 |
| 初始化中 | 丝杆锁止K66 | 就绪 | 排空完成 |
| 就绪 | 开始输注 | 运行中 | 调度启动 |
| 运行中 | 暂停 | 治疗暂停 | 暂停调度 |
| 治疗暂停 | 恢复 | 运行中 | 恢复调度 |
| 运行中/暂停 | 废止 | 废止 | 停止所有输注 |
| 任何运行态 | 一级报警 | 对应安全处理 | 停止输注（堵塞/机械故障） |

- 关键接口：`pump_state_t state_machine_get(void);` `bool state_machine_transit(pump_event_t ev);`
- **约束**：治疗位（stop/pause/run）至少置一位；run 仅在 op-ready 时置位（对齐 11073 OpStat 契约）。

### 3.3 AlarmApp（报警管理）

- 类型：`app/alarm_app.c/.h`
- 职责：接收 AlarmEngine 的分级报警，触发 BeeperDriver 与上报。
- 关键接口：
  - `void alarm_app_raise(alert_level_t level, uint16_t bit);`
  - `void alarm_app_clear(uint16_t bit);`
  - 一级：持续蜂鸣 + 立即上报；二级：断续（30s循环）+ 上报；三级：3次循环 + 上报。

## 4. 服务层设计（Service Layer）

### 4.1 BasalScheduler（基础率调度）

- 类型：`services/basal_scheduler.c/.h`
- 数据：48 段基础率表 `float basal_table[48]`（IU/h），当前曲线索引。
- 调度逻辑：
  1. 每 **3 分钟**定时唤醒（TIMER_3MIN）；
  2. 计算当前时段 `seg = (now_hour*60 + now_min)/30`；
  3. 段基础率脉冲 = `basal_table[seg] × 0.5 / 0.00339`（0.5h 内脉冲数）；
  4. 非整数脉冲量按**匀距分配**到该时段内；
  5. 累加已注射基础率。
- 关键接口：
  - `void basal_scheduler_load(const float table[48]);`
  - `void basal_scheduler_start(void);` / `void basal_scheduler_pause(void);` / `void basal_scheduler_resume(void);`
  - `uint32_t basal_scheduler_compute_ticks(uint8_t seg);` — 返回该段脉冲数。
  - `void basal_scheduler_tick(void);` — 3分钟周期槽。

### 4.2 BolusScheduler（大剂量调度）

- 类型：`services/bolus_scheduler.c/.h`
- 支持三种大剂量：

| 类型 | 说明 |
|------|------|
| 快速 Bolus | `剂量/0.00339` 一次连续输出 |
| 扩展 Bolus | 按基础率方式在扩展时间内分布 |
| 复合 Bolus | 前半立即输注（bolus 部分）+ 后半按基础率方式分布（扩展部分） |

- **双波切换去重**（对齐 RSK-04）：
  - bolus 部分输注完成 → 标记`phase=DONE_BOLUS` → 切换到扩展部分；
  - 扩展部分按时序均匀输出；
  - **防叠加**：切换瞬间禁止新脉冲命令，直到缓冲为空（`pulse_busy=0`）。
- 关键接口：
  - `bolus_status_t bolus_scheduler_start(const bolus_spec_t *spec);`
  - `void bolus_scheduler_stop(bolus_stop_reason_t r);`
  - `void bolus_scheduler_tick(void);` — 每 30ms 时隙分配下一脉冲。
- 幂等：大剂量命令带 `op_id`，已执行命令去重（见 BLE §6）。

### 4.3 ReservoirMonitor（药量监测）

- 类型：`services/reservoir_monitor.c/.h`
- 数据：
  - 物理位置→药量线性映射表 `uint8_t grid_seq[64]`（蛇形物理次序）。
  - 当前物理位置 `cur_pos`、当前药量 `cur_reservoir_ml`。
- 关键实现：
  - 药量 = `(物理序号-1)/63 × 2.0 ml`（序号1=K7=0ml → 序号64=K57=2ml）；
  - K7 接通 → **用尽**（一级报警）；K1（0ml端第7位）→ **药量低**（二级报警）；
  - 药量变化用于**输注反馈校验**（与理论输注量比对，超 3.5IU → 堵塞）。

### 4.4 ClockMgr（时钟）

- 类型：`services/clock_mgr.c/.h`
- RTC 连续运行，日误差 ≤1s。
- 首次绑定由 APP 设置时间；**每小时对时**（BLE 时间同步）。
- 关键接口：
  - `void clock_mgr_set(const rtc_datetime_t *t);`
  - `void clock_mgr_get(rtc_datetime_t *t);`
  - `bool clock_mgr_need_sync(void);` — 距上次同步>1h 返回 true。

### 4.5 Ieee11073 / BleService（通信）

- 见《完整API/BLE通讯协议文档.md》详细设计。
- 核心：GATT Service 180F、Char 2A20（write/notify）/2A21（read），agent 对象模型，命令接收/校验/回执。

### 4.6 LogManager（日志）

- 类型：`services/log_manager.c/.h`
- 环形缓冲工作状态日志（时间戳+事件码），FlashStore 持久化，支持 BLE 导出。
- 关键接口：
  - `void log_manager_append(const log_entry_t *e);`
  - `uint16_t log_manager_export(uint8_t *buf, uint16_t max);`

## 5. 驱动/HAL 层设计（Driver/HAL）

### 5.1 PWM（电机驱动）

- 类型：`drivers/pwm_motor.c/.h`
- PWM1（针6）、PWM2（针7）轮流输出 **20ms** 宽脉冲，间隔 30ms。
- 每脉冲转子转 180°，输注 0.00339 IU。
- 关键接口：
  - `void pwm_motor_init(void);`
  - `void pwm_motor_pulse_once(pwm_phase_t phase);` — 输出单脉冲。
  - `bool pwm_motor_busy(void);`
- 关键算法（`PulseDriver`）：脉冲序列输出 + **霍尔校验**（连续10脉冲无信号 → 机械故障）。

### 5.2 GridScanner（滑动格栅扫描）

- 类型：`drivers/grid_scan.c/.h`
- 8×8 开关矩阵（针8~12,23,27,28 行 + 针15~22 列），K1~K64。
- 扫描方式：行选通+列检测，逐行扫描定位唯一接通键。
- **关键**：物理位置 → 序号映射必须用**蛇形物理次序表** `grid_seq[64]`：
  `K7,K6,K5,K4,K3,K2,K1,K8,K9,...,K57`（0ml→2ml 端）。不可按格号相减。
- 关键接口：
  - `uint8_t grid_scan_position(void);` — 返回物理序号(1..64)。
  - `bool grid_is(K1..K66);` / `bool grid_is_pin_needed(void);`（K65 针到位）。

### 5.3 Hall（霍尔检测）

- 类型：`drivers/hall_sensor.c/.h`
- 针24 霍尔信号，中断检测转子是否转动（输注反馈）。
- 关键接口：`uint32_t hall_get_pulse_count(void);`

### 5.4 ADC_Battery（电池检测）

- 类型：`drivers/adc_battery.c/.h`
- 电池电压检测：<1.8V 耗尽（一级）、<2.0V 电量低（二级）；<2.0V 进旁路（ON/BYP 针37）。
- 关键接口：`uint16_t adc_battery_read_mv(void);`

### 5.5 Beeper（蜂鸣/震动）

- 类型：`drivers/beeper.c/.h`
- 针5 (beep)。按报警类型输出模式：一级持续、二级断续30s循环、三级3次循环。

### 5.6 RTC / FlashStore / GPIO_ISR

- **RTC**：连续时钟（日误差≤1s）。
- **FlashStore**：出厂信息、曲线、日志的掉电持久化（nRF Flash / FDS / pstorage 抽象）。
- **FlashStore 布局**：见《数据库详表.md》（闪存存储布局）。
- **GPIO_ISR**：灌注唤醒（推杆回退中断）、霍尔输入、K65/K66 到位检测等外部中断。

## 6. 关键算法细化

### 6.1 基础率 3 分钟脉冲换算

```
func basal_pulses(seg_rate_IUh, period_h=0.5):
    # 0.5h 内应输注的 IU
    iu_half = seg_rate_IUh * 0.5
    return floor(iu_half / 0.00339)          # 整数脉冲
```

- 非整数余量按**匀距分配**（每 3 分钟槽内累计，凑整后补发）。

### 6.2 快速大剂量

```
func fast_bolus_pulses(dose_IU):
    return round(dose_IU / 0.00339)
```

### 6.3 扩展大剂量

- 在扩展时间内按基础率方式分布：每 3 分钟槽脉冲 = `extension_IU×(3/60)/0.00339` 匀距。

### 6.4 复合大剂量

- 前半（bolus 比例）立即连续输注；
- 后半（扩展比例）按扩展时间分布；
- **切换点**：bolus 完成 → wait pulse_busy=0 → 启动扩展部分（防叠加）。

### 6.5 格栅药量映射

```
reservoir_ml = (grid_seq_index - 1) / 63.0 * 2.0
```

### 6.6 堵塞检测

- 理论累计输注量 与 格栅实测药量差 > 3.5IU → 堵塞（一级）。

## 7. 异常与边界处理

| 场景 | 处理 |
|------|------|
| 电池<1.8V | 一级耗尽报警 + 进旁路 + 停止输注 |
| 电池<2.0V | 二级电量低报警 |
| 堵塞 | 一级报警 + 停止输注 |
| 机械故障(连续10脉冲无霍尔) | 一级报警 + 停止 |
| 药液用尽(K7) | 一级报警 + 停止 |
| 双波叠加 | 切换点等待缓冲清空 |
| 命令重试 | op_id 幂等去重 |

## 8. 初始化序列（FW-D1 引导）

1. 时钟/电源初始化；
2. FlashStore 载入出厂信息；
3. GPIO_ISR 配置（灌注唤醒、霍尔、K65/K66）；
4. SoftDevice 初始化 + BLE 广播；
5. 各服务初始化（调度/监测/报警/日志）；
6. 进入状态机初始状态。
